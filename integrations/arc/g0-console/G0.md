# G0: Funcaster Pot workflow-verification scaffold

Status: scaffold only. Nothing in this repository is a production escrow.

## Purpose

G0 proves the project workflow end to end (create, build, test, export) before any contract work starts. It ships a small read-only diagnostic page for the Funcaster Pot project.

## G0 scope (read-only)

The page talks to one public JSON-RPC endpoint and nothing else.

| Item | Default |
| --- | --- |
| Network | Arc Testnet, chain ID `5042002` |
| RPC | `https://rpc.testnet.arc.io` |
| USDC | `0x3600000000000000000000000000000000000000` (6 decimals) |
| Public project relayer | `0x81DdeD7eE7753791cEaF24Ab6Cb1694d1F39A008` |

Reads are consistent: the chain ID is checked first, then the block number is read, then `decimals()` and `balanceOf` are both pinned to that same block. A token that does not report six decimals is rejected and no balance is shown. Configuration refuses any chain other than Arc Testnet (5042002).

It shows: connection status, observed chain ID, the public relayer address, the relayer's USDC balance in 6-decimal base units, the latest block number, and the time of the last check. A Refresh button re-reads. A wrong chain or a failed RPC is shown as an error, and no value is invented or cached to hide it.

Every page carries the permanent label `PLAY MONEY · ARC TESTNET`. All amounts are test funds with no real value.

### Hard boundary for G0

- No wallet connection and no signatures.
- No private keys, and no credentials in source or in the browser.
- No faucet requests.
- No transactions on any public chain and no contract deployment.
- No paid upgrade and no production hosting.
- The only network interaction in the app is public RPC reads (`eth_chainId`, `eth_blockNumber`, and `eth_call` for `decimals` and `balanceOf`). There is no telemetry, no console upload, no parent-window messaging, and no remote fonts or scripts. The Arc Studio attribution is a normal footer link that loads nothing.

Optional public overrides (never secrets): `VITE_CHONKS_CHAIN_ID` (accepted only if it is `5042002`), `VITE_CHONKS_RPC_URL` (https only), `VITE_CHONKS_USDC_ADDRESS`, `VITE_CHONKS_RELAYER_ADDRESS`. Invalid values fail loudly at startup.

## Future target: ConditionalPot

A later project, explicitly not part of G0. The intended design:

- No admin. No owner, no operator role, no pausing, no upgrade path, no proxy.
- 2 to 4 seats per pot.
- Funds in USDC or EURC.
- Sponsored funding through ERC-3009 `receiveWithAuthorization` (the `bytes signature` overload), so a relayer can submit a seat's signed authorization without the player holding gas. `receiveWithAuthorization` is payee-only: the token requires the caller to be the `to` address, so the pot contract itself must be the payee and the caller, and a third party cannot front-run the authorization. `transferWithAuthorization` is deliberately not used. Whether the Arc Testnet USDC and EURC contracts expose the `bytes signature` overload must be confirmed against their deployed interfaces before implementation; G0 does not verify it.
- Settlement in one of two ways: unanimous agreement among the seats, or an oracle proposal that any seat can contest.
- Refund by default: if a pot is not settled, every seat can recover its own deposit.
- Independent pull claims: each seat withdraws its own share, and one seat's claim can never block or depend on another's.
- No fees and no upgrades.

### Gate before any live deployment

At least 40 Foundry tests covering funding, settlement, oracle proposal and contest, refund, claims and failure paths must pass first. Any deployment is a separate, explicitly approved step after those tests and a review. G0 does not deploy anything.

## Verification

```bash
bun install
bun run test        # vitest: formatting, addresses, config, pinned reads, decimals, wrong chain, UI states
bun run typecheck   # tsc --noEmit
bun run check       # tests, then typecheck
bun run build       # vite production build
```
