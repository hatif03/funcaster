# Funcaster creator commerce — Arc Studio source provenance

Create a NEW app containing RevenueRouter.sol and focused Foundry tests. Do not deploy anything, sign transactions, send public transactions, or request/fund keys. This is source generation and local test execution only. Preserve the Funcaster brand. Give the app a descriptive Funcaster Creator Commerce name.

Build a minimal non-upgradeable RevenueRouter for Arc testnet 5042002 using Solidity 0.8.28, optimizer 200, Cancun, OpenZeppelin 5.x. Commerce is separate from wager pots and markets. It supports only constructor-pinned USDC (6 decimals) initially; EURC is deliberately excluded because USD threshold conversion needs a documented rate.

An immutable operator registers immutable versionId bytes32, creator, uint256 price (max 100 USDC, positive), platform, optional venue (10%), optional referral (500–2000 bps), and up to five collaborators whose relative weights including creator total exactly 10000. Versions cannot be changed. Constructor platform, token, operator nonzero. Freeze standard fee 1000bps, creator-brought 500bps, hard cap 1500. Global lifetime gross per creator (across versions) receives a free first 1000 USDC band; a payment crossing the threshold charges only the portion above it. Creator remainder after platform/venue/referral is allocated using integer floor and ALL dust goes to creator, conserving exact amount. Fee schedule must not be changed by owner.

Payment must bind idempotent paymentId, version, payer, roomHash, attribution bool and validity into an EIP712 PassPermit signed by payer. Verify exact registered price. Receive payment using token.receiveWithAuthorization (EIP3009 bytes v/r/s; to=this, value=price, nonce/paymentId linked, validAfter/validBefore bounded; reject expired permit). Operator is allowed to relay pay, not forge payer signature. Credit each recipient independently, update lifetime, emit PassPaid(paymentId,versionId,payer,roomHash,amount). No recipient transfer during pay. One pass buys 24 hours for exact version/room. Claim via EIP712 ClaimPermit for recipient, fixed recipient destination, nonce and deadline; anyone can relay; consumes nonce only in successful claim. Pull credit is token balance accounting; checks effects interactions with ReentrancyGuard and SafeERC20; if a recipient is blocklisted/reverts, their claim reverts without affecting others. No owner withdrawal of accounted credits, no arbitrary calls, no extra fee/rake. Public credit and pass-expiry getters.

Tests: exact conservation and rounding dust, free band crossing and cross-version creator counter, creator-brought rate, immutable version/fee/referral boundaries, replayed payment and claim, tampered permit/authorization, unrelated recipient can claim when one recipient blocked. Use local mock EIP3009 token and local ephemeral keys only. Document ABI and JSON call examples, compile source/artifacts and leave them accessible for CLI pull. Do not build a front-end; parent task handles UI. Never modify another Studio app. Report local test results and exact paths.
