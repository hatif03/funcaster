# Optional Kart peer-lockstep laboratory

Online Kart/Tennis/Fencing now use server-owned simulation and snapshots. This laboratory explores a possible future peer-simulation alternative; it is not required to enable online play. It does not accept production room tokens or write party results.

1. Run `npm run test:determinism -- /tmp/chonks-kart`. It runs 20 full three-lap races twice in native math and twice in explicit math, with checkpoint hashes and fast-forward timing. Each mode must agree with itself; the two math modes are not expected to produce identical trajectories.
2. With the normal development server open, visit `/determinism` in Chrome, Firefox, Safari, iOS and Android. Run each mode, save the timeline, and compare like modes on the same build. Twenty complete hash-equal races on every required engine are the gate.
3. Run `npm run lab:lockstep`. It binds only `127.0.0.1:8667` (override port with `LAB_PORT`). Create a lab on one screen; join its code on a second screen and in the phone role. Start a seeded race, use the touch steering slider/pedals and test delivery delays from 0–500 ms. The normal phone motion calibration remains tested separately. A real phone needs an explicitly configured HTTPS proxy to this isolated lab; do not expose the production namespace to fake lab credentials.
4. Compare checkpoint counts, mismatches, stalls and largest catch-up cost. Missing/duplicate/reordered frames are buffered and recovered from the bounded server log. Missing phone samples become autopilot. Repeat five complete live races. Record device/browser/build, network, delay, hash result and timing in the release evidence.

The sequencer stamps 60 Hz frames with a six-frame input delay; each frame drives two 120 Hz physics steps. The lab limits rooms, two screens/two phones, payloads, logs and session lifetime. It uses a top-down diagnostic map rather than the production renderer, so its timings do not establish the four-view GPU budget. Existing unit tests check 10,000 sequenced frames with duplication/reordering and stale input.

**Do not switch production to peer lockstep on this evidence.** Shared pause/recovery and online Tennis/Fencing are implemented separately through server simulation. Only a future peer-lockstep change depends on this lab’s cross-engine gate. Real-device hash differences require another math/serialization pass, not a relaxed comparison threshold.
