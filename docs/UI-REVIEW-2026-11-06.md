# UI review — 6 November 2026

Scope: the complete user-facing arcade in [PR #2](https://github.com/hatif03/web3-multiplayer-games/pull/2), on `codex/arcade-launch-plan`. This pass combines source review, real browser interactions, screenshots and DOM rectangle checks. It is not a physical-phone acceptance result.

## Regressions corrected

- The remote-screen controller link and Ready button overlapped. Pairing now has explicit wrapping action rows, a responsive QR section and a separate game stage.
- Narrow lobby options overflowed horizontally, and the expanded extras panel mixed cream text with a cream background. Forms now stack within a fluid grid and use the arcade palette.
- Phone diagnostics links ran into the next settings button. Settings actions now occupy separate full-width rows; long dialogs scroll, preserve their close button and retain usable controls.
- Compact portrait controllers pushed the main action below the initial screen. Short portrait layouts now use a smaller touch pad and tighter nonessential decoration while retaining the action and three utility buttons.
- Legacy game instructions collided with the connection badge. A shared status rail gives both their own layout area; Drawing reserves the left-hand palette's space.
- Independent split-screen player badges covered instructions. Player badges now sit between the corner HUDs, with dark readable text on the seat color.
- The Kart Rush menu used viewport-scaled text and clipped key choices at small heights. It now has bounded fonts, scroll-safe content and a compact landscape grid with visible driver, lap and confirmation controls.
- Shared-world game headers could crowd their timer and multi-player scores. Titles/timers have separate columns, with wrapping score chips below.
- Result dialogs inherited conflicting light/dark styles. Rankings, descriptions, statistics and wrapping actions now use a consistent dark palette and bounded scrolling.
- Paired Tennis/Fencing player labels could retain the wrong seat color, and bright sky backgrounds reduced label contrast. Labels follow the rendered perspective and have a dark backing.
- Switching between shared games could leave every mode button unselected. Host and phone setup now show the normalized settings that the server will use.
- A spectator's player selector could become blank after leaving an online duel. Non-classic shared arenas explicitly show Everyone; the lobby no longer mentions a hidden pairing QR.
- Results counted down to “another round” even though they return to the lobby. The caption now accurately describes returning to the game room with phones still connected.
- Desktop server-game arenas could push their footer controls below the screen. Their canvas now flexes within the remaining viewport height.
- Diagnostics, creator preview, Credits and community gallery have consistent readable typography, wrapping and mobile-safe controls. Gallery isolation and content security policy are unchanged.

## Validation and review boundaries

- `npm run check`: **300 unit tests and 68 party tests pass**, with all 13 catalog entries and bundles validating.
- `npm run format:check`, formatting checks for changed source files and `git diff --check` pass.
- CI exposed a race in the existing online-Kart test: its fake clock could advance before confirm messages arrived. Socket acknowledgement barriers now precede the assertions; assertions and production behavior are unchanged. The six-test shared-round suite passed ten consecutive runs, followed by all 68 party tests.
- Four-player rules, lifecycle and online simulation are covered by the automated suite. This visual pass used three distinct browser-controller identities, not four real devices.
- No new authority, sensor mapping, game rules, publication privileges or deployment were introduced by this UI pass. Backend delivery remains PR-only.

Real iOS/Android motion, physical multitouch, mobile safe-area/browser chrome, accessibility with actual assistive technology, mixed networks and the one-hour thermal soak remain in [the current plan](../plan.md). The outside-creator trial and stable hosting remain separate acceptance/deployment work. Optional lockstep research and its diagnostic tools are not part of the public player flow.
